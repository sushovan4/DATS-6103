Merging and Combining Datasets


5 minutes

The answer to a question is rarely in one table. Deaths are in one file and population in another, and the join is where the analysis actually happens.

pd.merge does it, on one or more columns called keys, the same way a SQL join does. The mechanics are easy. What is not easy is noticing when a merge has gone wrong, because it does not raise: a key that matches nothing silently drops rows, and a key that matches more than once silently multiplies them. Count your rows before and after every join you write. That habit is worth more than the syntax below.

For the ease of exposition, we use two real datasets: death-rates.csv and drug-overdose.csv. Feel free to check the Kaggle pages to learn more about the datasets and their metadata.

Note that the merged dataset contains all columns of both datasets—except for YEAR.

Note that the years in the result are the intersection, or the common set found in both datasets. This is an instance of inner join. There are other variants (left, right, outer), which can be mentioned using the how argument of .merge.
