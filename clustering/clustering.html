Clustering


14 minutes

Everything in the course so far has had an answer key. You were given labels, you fitted something to predict them, and you could say afterwards how often you were right.

Now the labels are gone. You have a table and a suspicion that the rows fall into groups, and no way to check. That changes what “correct” can mean: there is no accuracy to compute, because there is nothing to compare against. What you can ask is whether a grouping is tight – whether points in the same cluster are close to each other – and that question turns out to have an exact answer, an algorithm that cannot reach it, and a set of assumptions that will quietly ruin your results if the data does not meet them.

Centroid-based Paritioning

Input: A dataset X\subset\mathbb{R}^d containing n objects and k\in\{1,2,\ldots,n\}

Output: Partition X into clusters \{C_1,C_2,\ldots,C_k\} such that

  • C_i\subset X
  • |C_i|\geq1
  • C_i\cap C_j=\emptyset, for i\neq j.

Objective: Minimize the within-cluster variation by miniming the objective function: E=\sum_{i=1}^k\sum_{p\in C_i}\|p-c_i\|^2, where c_i denotes the centroid of C_i.

Bad news: finding the partition that minimises E is \mathcal{NP}-hard. Not slow – infeasible. For n points and k clusters there are roughly k^n/k! partitions, so at n=100 and k=3 you would be checking more of them than there are atoms nearby.

That is why the rest of this chapter is about an algorithm that does not solve the problem. k-means finds a local minimum of E, not the global one, and every practical consequence below follows from that sentence.

k-Means: A Greedy Partitioning

Data objects are put into clusters greedily using their nearest centroids

# Input:
#   - X: a list of n number of tuples (x1, x2,...,xd)
#   - k: a positive integer, 1<=k<=n

# Output:
# A set of k clusters

- Randomly choose k objects from X as the centroids

while(clusters are not stable):
    - (re)assign each object to the cluster of the nearest centroid
    - update the cluster centroids, by calculating the mean of objects
return clusters

Concluding Remarks

Pros

  • extremely easy to implement
  • computationally very efficient
  • can be applied to data of any dimension

Cons:

  • good at identifying clusters with a spherical shape
  • sensitive to the initial choice of centroids
  • need to define the number of clusters, k, a priori

One iteration of k-means

The whole algorithm is two steps repeated: assign every point to its nearest centroid, then move every centroid to the mean of the points assigned to it. Do one round by hand.

Store the assignment in labels and the updated centroids in new_centroids.

labels = d.argmin(axis=1)
new_centroids = np.array([X[labels == j].mean(axis=0) for j in range(len(centroids))])
