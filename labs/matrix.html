1. What + means, and why NumPy added no new command

“Python’s list can hold a vector’s numbers, but + glues two lists together instead of adding them element by element. Does NumPy add a new command to address this?”

“Can adding up vectors still be done with just Python, and if so, is it less efficient?”

No new command. a + b asks the object on the left what + means, and ndarray answers differently from list:

Plain Python works too—[x + y for x, y in zip(a, b)]—and is 7x slower at n=1000, 130x at n=100{,}000. But both are under a millisecond at n=1000. Speed is not why we use NumPy today. + meaning the right thing is.

2. Reading a comprehension, and the subscript that moves

“How is len(r) being calculated when it is not defined?”

for r in ragged defines it, one element at a time.

Each r is itself a list, so len(ragged) counts rows and len(r) counts entries in one row. Nothing errors, and only the second line tells you this is not a matrix.

“Would the result differ completely if we started with x=1?”

No—and that is why it bites. The index is a label, not data, so a forgotten shift returns a real entry of a real vector that happens to be the wrong one.

3. * is not matrix multiplication

“Must the NumPy convention be applied in all mathematical equations, or can it be replaced by standard operators like + or *?”

The operators are already defined, so there are no new names to learn. One exception, and it will cost somebody an hour tonight:

Both run, both return a 2\times2, and only @ is the \bold{AB} of these notes. Every problem in Part B uses @.

4. When a distance stops meaning anything

“Is the distance between two vectors calculated using the norm between them, even if the units are different?”

The formula is \|u-v\| and it does not care. Whether the answer means anything is a different question:

The nearest neighbour flips. Same people, same facts, only the unit changed. Each column enters the sum on its own scale, so in dollars a 25-year age gap counts for less than rounding noise in salary. Standardize first—this returns when we scale features for k-NN.

“With a big dataset how do we make sure the order stays consistent?”

You stop using positions. A swapped column returns a plausible number rather than an error, so the defence is names, not care: MIDTERM, FINAL = 0, 1 today, assertions on the header when the file is real.

A1. Split it in two

Phone screen, quantitative research.

“Take any square matrix \bold{A}. Can you always write it as a symmetric matrix plus a skew-symmetric one? Convince me.”

Rubric card—interviewer only

A good answer contains:

  • The construction, not just the claim: \bold{A}=\tfrac12(\bold{A}+\bold{A}^\top)+\tfrac12(\bold{A}-\bold{A}^\top).
  • A verification of each half: (\bold{A}+\bold{A}^\top)^\top=\bold{A}^\top+\bold{A}, so the first piece is symmetric; the same computation flips the sign on the second, so it is skew.
  • Where squareness is used—\bold{A}^\top has to have the same shape as \bold{A} before you can add them at all.
  • Ideally: the diagonal of the skew part is zero, so the symmetric part carries the whole diagonal of \bold{A}.

Common wrong answer to listen for: “Yes—take the upper triangle as the symmetric part and the lower triangle as the skew part.” This pattern-matches the shape of the answer without producing two matrices that add back to \bold{A}. Ask them to add their two pieces on a 2\times2 example.

Follow-up probe: “Point at the exact step where you used that \bold{A} is square.”

A2. Is it the only way?

Same conversation, one question later.

“Fine. Is that decomposition unique, or is it just one of many?”

Rubric card—interviewer only

A good answer contains:

  • The right reduction: if \bold{S}_1+\bold{K}_1=\bold{S}_2+\bold{K}_2 then \bold{S}_1-\bold{S}_2=\bold{K}_2-\bold{K}_1, and that single matrix is symmetric and skew-symmetric.
  • The lemma, proved: if \bold{M}=\bold{M}^\top and \bold{M}=-\bold{M}^\top then \bold{M}=-\bold{M}, so 2\bold{M}=\bold{0} and \bold{M}=\bold{0}.
  • The conclusion drawn: the difference is zero, so \bold{S}_1=\bold{S}_2 and \bold{K}_1=\bold{K}_2. Unique.
  • Ideally: the observation that both A1 and A2 divide by 2, and that this is where “real entries” is quietly doing work.

Common wrong answer to listen for: “It’s unique because I only found one formula.” Failing to find a second one is not an argument. Make them say what would have to be true for a second decomposition to exist.

Follow-up probe: “Write me a nonzero matrix equal to its own negative transpose. Now write me one that is both symmetric and skew.”

A3. Order matters

Onsite, machine learning engineer.

“Give me two 2\times2 matrices with \bold{AB}\neq\bold{BA}. Then tell me why I should have expected that before you wrote anything down.”

Rubric card—interviewer only

A good answer contains:

  • An explicit pair, multiplied both ways out loud. \begin{bmatrix}0&1\\0&0\end{bmatrix} and \begin{bmatrix}0&0\\1&0\end{bmatrix} is the cheapest.
  • The reason, not the rule: a matrix is a function, \bold{AB} means “do \bold{B}, then \bold{A}”, and swapping the order of two operations generally lands somewhere else.
  • A geometric instance: rotate then project versus project then rotate.
  • The families that do commute—diagonal matrices, a matrix with its own powers, a matrix with its inverse, anything with \bold{I}—and why those are special rather than typical.

Common wrong answer to listen for: “Matrix multiplication just isn’t commutative, that’s the rule.” True, and useless: it explains nothing and predicts nothing. Ask them to predict, without computing, whether two diagonal matrices commute.

Follow-up probe: “Does \bold{A} commute with \bold{A}^2? With \bold{A}^{-1}? What do those two cases have in common?”

A4. When you cannot multiply at all

Whiteboard round, data science generalist.

“Give me two matrices that cannot be multiplied. Then tell me what the shape rule is really enforcing.”

Rubric card—interviewer only

A good answer contains:

  • The rule stated precisely: an m\times n times a p\times q needs n=p; two 2\times3 matrices are the cheapest illegal pair.
  • The reason underneath it: every entry of \bold{AB} is a dot product of a row of \bold{A} with a column of \bold{B}, and two vectors of different lengths have no dot product.
  • The composition view: \bold{B} maps \mathbb{R}^q\to\mathbb{R}^p and \bold{A} maps \mathbb{R}^n\to\mathbb{R}^m, so they chain only when \bold{B}’s output space is \bold{A}’s input space.
  • The kicker: \bold{AB} can be defined while \bold{BA} is not—a second, cruder reason to expect \bold{AB}\neq\bold{BA}.

Common wrong answer to listen for: “You can’t multiply them if they’re different sizes.” Different sizes are the normal case. Exactly one dimension has to agree, and naming which one is the whole question.

Follow-up probe: “\bold{AB} comes out 2\times2 and \bold{BA} comes out 3\times3, same two matrices. What were their shapes?”

A5. What singular costs you

Onsite, quantitative / machine learning role.

“\bold{A} is n\times n and singular. Can you find a matrix \bold{B}, not the zero matrix, with \bold{AB}=\bold{0}?”

Rubric card—interviewer only

A good answer contains:

  • Singular means the columns are linearly dependent, so some nonzero \bold{v} has \bold{Av}=\bold{0}.
  • The construction: put that \bold{v} in every column of \bold{B} (or in one column, zeros elsewhere). Each column of \bold{AB} is \bold{Av}=\bold{0}, so \bold{AB}=\bold{0} while \bold{B}\neq\bold{0}.
  • Why the same trick is impossible when \bold{A} is invertible: multiply \bold{AB}=\bold{0} by \bold{A}^{-1} on the left and \bold{B}=\bold{0} falls out.
  • What it costs in data work: \bold{Ax}=\bold{b} then has no solution or infinitely many, never exactly one. The answer is not identified.

Common wrong answer to listen for: “\bold{AB}=\bold{0} means \bold{A} or \bold{B} is zero.” Cancellation is a property of numbers, not of matrices, and this is the most common thing carried over from scalar algebra that is simply false here.

Follow-up probe: “You multiplied both sides by \bold{A}^{-1} somewhere. Say out loud what you assumed when you did that.”

A6. What \bold{Ax} actually is

Take-home follow-up discussion, applied machine learning.

“Explain what \bold{Ax} is, geometrically. Then tell me what the set of all possible \bold{Ax} looks like, and why \bold{Ax}=\bold{b} might have no solution at all.”

Rubric card—interviewer only

A good answer contains:

  • \bold{Ax}=x_1\bold{a}_1+\cdots+x_n\bold{a}_n: a weighted combination of the columns of \bold{A}, with the entries of \bold{x} as the weights.
  • The set of all \bold{Ax} is therefore the span of the columns—a line, a plane, or something bigger, always through the origin. Its dimension is the rank, which can be smaller than the number of columns.
  • If \bold{b} does not lie in that span, no \bold{x} solves \bold{Ax}=\bold{b}, and no solver will change that. B5 is this question answered with two dot products.
  • What is done instead: take the point of the span closest to \bold{b}, and look at the vector left over—the one running from that point to \bold{b}. Closest means that leftover is perpendicular to the span, because any part of it lying along the span could be slid away to get closer. And perpendicular to the span means it dots to zero against every column. That is the whole reason the dot product keeps appearing beside the span.

Common wrong answer to listen for: “\bold{Ax} is a bunch of dot products of the rows with \bold{x}.” That is true and it is the right way to compute it, but it is the wrong way to see what is reachable. Ask which view answers the question you asked.

Follow-up probe: “Your matrix has 1000 rows and 5 columns. \bold{b} lives in a space of what dimension? And the reachable set is of what dimension? Now tell me how often you expect \bold{Ax}=\bold{b} to have a solution.”

B1. The decomposition, computationally

You argued in A1 that every square matrix splits into a symmetric part plus a skew-symmetric part. Now build it and test it on matrices nobody chose by hand.

Write decompose(A) returning the pair (S, K) with S symmetric, K skew-symmetric, and S + K equal to A. It must work for any square A, of any size.

def decompose(A):
    A = np.asarray(A, dtype=float)
    return (A + A.T) / 2, (A - A.T) / 2

claim_b1 = ("One hand-picked matrix can pass by a coincidence in the numbers "
            "chosen, whereas four sizes drawn at random can only pass if the "
            "identity holds for every square matrix.")

The symmetric part is the average of \bold{A} with its transpose, the skew part half the difference, and they add back to \bold{A} because \frac{A+A^T}{2}+\frac{A-A^T}{2}=A.

Transposing \bold{S} swaps the two terms of a sum and leaves it alone; transposing \bold{K} swaps the two terms of a difference and negates it. The zero diagonal comes free: k_{ii}=(a_{ii}-a_{ii})/2.

Nothing in those two lines mentions the size, which is why it passes at n=2,3,5 and 8 without change. That is the point of testing on random matrices—one hand-picked example can pass because of a coincidence in the numbers you chose; four sizes drawn at random cannot.

B2. Hunting a counterexample

In A3 you produced a non-commuting pair by hand. Now let the machine do it, and find out how unusual commuting really is.

  1. Search random integer 2\times2 matrices until you find a pair with \bold{AB}\neq\bold{BA}. Store them as A_nc and B_nc.
  2. Draw 1000 random pairs the same way and count how many commute. Store the count in n_commuting.
  3. Produce a pair that does commute, where the two are different from each other and neither is a multiple of the identity. Store them as A_c and B_c. Think about A3’s last bullet before you start guessing.
while True:
    A_nc = rng.integers(-3, 4, size=(2, 2)).astype(float)
    B_nc = rng.integers(-3, 4, size=(2, 2)).astype(float)
    if not np.allclose(A_nc @ B_nc, B_nc @ A_nc):
        break

n_commuting = 0
for _ in range(1000):
    P = rng.integers(-3, 4, size=(2, 2)).astype(float)
    Q = rng.integers(-3, 4, size=(2, 2)).astype(float)
    if np.allclose(P @ Q, Q @ P):
        n_commuting += 1

A_c = np.array([[1., 2.], [3., 4.]])
B_c = A_c + np.eye(2)

claim_b2 = ("Matrix multiplication is not commutative in general: only 11 of 1000 "
            "random pairs commuted, so AB = BA is a special property of a pair "
            "rather than a rule you may assume.")

Step 1 usually finds a counterexample on the first draw. Step 2 is the number worth carrying: about 11 pairs in 1000 commute, near one percent, and most of those are degenerate—a multiple of the identity, or a repeated matrix.

So \bold{AB}=\bold{BA} is not a mild technicality that usually holds. It is the rare exception, and writing \bold{AB} when you meant \bold{BA} gives a different matrix almost every time.

Step 3 is the one people guess at. Guessing does not work; the construction does. Any polynomial in \bold{A} commutes with \bold{A}, because both products multiply out to the same sum of powers. \bold{A}+\bold{I} is the cheapest choice and \bold{A}\bold{A} works equally well—and neither is a multiple of the identity, which is what the restriction was there to force.

B3. A singular matrix and its null space

The matrix A below is singular. A5 told you that means there is a nonzero \bold{B} with \bold{AB}=\bold{0}. Build one.

  1. Record rank_A, the rank of A.
  2. np.linalg.inv(A) raises. Catch it, and record the name of the exception class as a string in inv_error.
  3. Find a nonzero vector v with A @ v equal to zero, by looking for a linear relation among the columns of A. You can do this by eye.
  4. Build a 3\times3 matrix B, not the zero matrix, with A @ B equal to zero.

The set of all such v has a name: the null space of A. Step 4 works because you can fill B with anything drawn from it.

rank_A = np.linalg.matrix_rank(A)

try:
    np.linalg.inv(A)
except np.linalg.LinAlgError as e:
    inv_error = type(e).__name__

v = np.array([1., 1., -1.])          # column 3 = column 1 + column 2
B = np.column_stack([v, v, v])

claim_b3 = ("A sends a whole line of nonzero vectors to the origin, so two inputs "
            "differing by anything on that line give the same output and the "
            "information needed to invert it is gone.")

rank_A is 2, not 3, and np.linalg.inv raises LinAlgError.

You can find v by eye, as promised, because the third column is exactly the sum of the first two: [3,1,6]=[2,1,4]+[1,0,2]. A dependence among the columns is a vector the matrix sends to zero—take the coefficients of the relation, here [1,1,-1].

For \bold{B}, any matrix whose columns all come from the null space will do, since \bold{A}\bold{B} is \bold{A} applied to each column in turn. Stacking v three times is the shortest such matrix that is not the zero matrix.

What it says about \bold{A}: it sends a whole line of nonzero vectors to the origin. Two inputs differing by anything on that line produce the same output, so the information is gone and no rule could recover it. That is what singular means, in the one sentence worth keeping.

B4. Determinant and inverse, checked against NumPy
  1. Write det2(M) and inv2(M) for 2\times2 matrices from the closed formulas, without calling anything in np.linalg. inv2 returns None when the matrix is singular.
  2. M below is invertible. Is M @ inv2(M) exactly the identity? Record True or False in exactly_identity. Use np.array_equal, not np.allclose, and print the product to see what you actually got.
  3. Over 100 random pairs of 3\times3 matrices, record in max_det_gap the largest value of |\det(\bold{PQ})-\det(\bold{P})\det(\bold{Q})| you see.
  4. C below is 4\times4 but built from a 4\times3 times a 3\times4, so it cannot have rank 4. Record det_C and rank_C.
def det2(M):
    M = np.asarray(M, dtype=float)
    return M[0, 0] * M[1, 1] - M[0, 1] * M[1, 0]

def inv2(M):
    M = np.asarray(M, dtype=float)
    d = det2(M)
    if d == 0:
        return None
    return np.array([[M[1, 1], -M[0, 1]],
                     [-M[1, 0], M[0, 0]]]) / d

exactly_identity = np.array_equal(M @ inv2(M), np.eye(2))

max_det_gap = 0.0
for _ in range(100):
    P = rng.normal(size=(3, 3))
    Q = rng.normal(size=(3, 3))
    max_det_gap = max(max_det_gap,
                      abs(np.linalg.det(P @ Q)
                          - np.linalg.det(P) * np.linalg.det(Q)))

det_C = np.linalg.det(C)
rank_C = np.linalg.matrix_rank(C)

claim_b4 = ("A singular matrix built by any real computation lands near zero rather "
            "than on it, so the exact test det(A) == 0 almost never fires and "
            "reports invertible for a matrix that is not.")

exactly_identity is False. Print the product and you see why: the diagonal is 1 and the off-diagonal entries are around 10^{-17} rather than 0. The algebra is exact; the arithmetic is not.

max_det_gap comes out around 10^{-14}—so \det(\bold{PQ})=\det(\bold{P}) \det(\bold{Q}) does hold, to rounding, which is the strongest form in which it can hold on a computer.

\bold{C} is the payoff. It is 4\times4 but built from a 4\times3 times a 3\times4, so its rank cannot exceed 3—rank_C is 3. Its determinant is therefore mathematically zero, and det_C comes back as something like 10^{-17} instead of zero.

Which answers the question: det(A) == 0 is a test that almost never fires. A singular matrix built by any real computation lands near zero, not on it, so the exact test reports “invertible” for a matrix that is not. Use np.linalg.matrix_rank, or compare |\det| against a tolerance—and be aware that the determinant also scales with the size of the entries, so there is no one threshold that is right for every matrix.

B5. Where \bold{Ax} can reach

This is A6 made concrete, and it is the problem this course keeps coming back to.

  1. Rebuild A @ x as a weighted sum of the columns of A, without applying @ to A. Store it in combo. (You did this with plain lists in §1.4; this is the same identity in NumPy.)
  2. Draw 500 random vectors x and form the 500 outputs A @ x. Store them as the rows of a (500, 3) array called reach.
  3. The vector n below is perpendicular to every column of A. Record in max_off_plane the largest |\,\bold{n}\cdot\bold{y}\,| over all rows \bold{y} of reach.
  4. Now take \bold{b}=(1,0,0) and record n_dot_b.
  5. From steps 3 and 4 alone—no solver—decide whether any x satisfies A @ x == b exactly. Record True or False in solvable.
combo = sum(x[j] * A[:, j] for j in range(3))

reach = np.array([A @ rng.normal(size=3) for _ in range(500)])

max_off_plane = np.max(np.abs(reach @ n))

n_dot_b = float(n @ b)

solvable = False

claim_b5 = ("A collapses space onto a plane: every output lies in that plane, so "
            "there are nonzero vectors it sends to the origin and b is solvable "
            "only when b lies in the plane.")

combo reproduces A @ x exactly, because it is A @ x—written as x_1\bold{a}_1+x_2\bold{a}_2+x_3\bold{a}_3 rather than as three row dot products. Same arithmetic, regrouped.

max_off_plane is about 10^{-15}: zero, to rounding. Every one of the 500 outputs satisfies \bold{n}\cdot\bold{y}=0. That is not a coincidence about these 500 draws—\bold{n} was chosen perpendicular to all three columns, and every \bold{A}\bold{x} is a combination of those columns, so every output inherits the property. The reachable set is a plane through the origin, not all of \mathbb{R}^3.

n_dot_b is 1. So \bold{b} fails the one test every \bold{A}\bold{x} passes, and solvable is False.

Notice what that argument did not need: no solver, no inverse, no row reduction. Two dot products settled it. And the rank story from B3 and B4 is the same story told another way—\bold{A} here has rank 2, which is exactly why its outputs fill a plane rather than space.

Where this goes

You have just shown that \bold{b} is off the plane every \bold{Ax} lands on, so no \bold{x} can reach it. Nothing in the rest of this course fixes that. What we do instead is settle for the closest point of the plane, and the vector from that point to \bold{b} turns out to be perpendicular to every column of \bold{A}—which is why max_off_plane mattered.
